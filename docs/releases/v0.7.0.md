Many more installers work, and AI apps, developer tools and game launchers run better.

**Already have Isolated?** It updates itself: open the window and choose **Update now**, or run `isolated update`. New users: download `isolated.exe` below, open it, and choose **Settings > Install for this user**.

### Installers
Isolated now borrows tricks from other sandbox and app-virtualization tools (Sandboxie, App-V, Cameyo, Turbo):
- **Setup programs that wrap `.msi` packages** (WiX bundles, used by many developer tools and runtimes) are unpacked instead of run.
- **Setup programs that hand an `.msi` to Windows Installer**, which can't work in a sandbox, have that package caught and unpacked into the box.
- **Portable apps in a `.zip`** install into a box: right-click the `.zip` and choose **Install in Isolated...**.
- Apps in a box get the box's own **ProgramData** and **Public** folders, and installers get the box's Programs folder as Program Files, so writes that would need administrator rights land in the box.
- NSIS installers are asked to install for the current user, the 64-bit package is picked when a bundle has both, and failures explain why (administrator rights required, Windows Installer, and so on).

### AI apps, developer tools and game launchers
- Command-line tools get a private `HOME`, so their dotfolders (`.cache`, `.config`, ...) stay in the box.
- **Node.js** can start in a container after a one-time approval: **Settings > App compatibility > Allow**, or `isolated system-compat` as administrator. It lets sandboxes see only that drives and the Users folder exist.
- **Chromium-based apps** (Electron AI apps, Steam, WebView2/Tauri apps, browsers) run in a box with the **compatible** profile. Isolated recognises them and turns off their inner sandbox, which can't start there. They still write only into the box.
- Python tools, local servers on `localhost`, and child processes are tested in containers on every build.

Verify the download: the SHA-256 is in `isolated.exe.sha256`.
